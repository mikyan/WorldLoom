## Context

当前 `PlayableScene` 只声明标签、描述、行动、参与者和背景图；`GuidanceProjector` 会把当前可执行的 Action、Activity、Travel 直接转换为玩家建议。该结构能够保证建议指向合法工具，却不能证明建议中的地点、人物和目标已经向玩家公开。

战争剧本开场因此产生认知断层：场景描述要求寻找水、药品和路线，却没有描述药房；唯一关键 Action 和首个 Hint 随即要求“搜查临街药房”。聊天记录又是瞬时信息，玩家缺少一个持续回答“我在哪、我知道什么、能去哪、为什么要做这件事”的界面。

本变更建立在现有 `player-guidance`、`playable-world-contract`、Command/Event 权威链、NPC 可见性隔离和三端 Compose UI 之上。地图和提示都属于玩家可见投影，不能读取世界包里的隐藏节点，也不能直接修改事实。

## Goals / Non-Goals

**Goals:**

- 让第一次接触跑团的玩家在每个场景都理解地点、目标、压力、附近角色和可感知的行动对象。
- 提供带迷雾的节点地图，记录已到达、已发现、模糊线索和已知封锁，而不泄露完全未知地点。
- 让所有快捷建议都有玩家可见依据，并把“可执行规则出口”与“适合此刻展示的自然语言建议”分开。
- 通过示例、主动提示和停滞救援形成渐进式温和引导，同时保留自由输入。
- 让发现事实、保存、恢复和回放保持确定性；地图不成为第二套真相来源。
- 用战争剧本开场三个阶段验证内容、引导、地图和失败推进是否共同形成可玩的循环。

**Non-Goals:**

- 不实现格子战斗、连续坐标、寻路、碰撞或角色棋子移动。
- 不把完整世界图、隐藏 NPC、秘密路线或结局条件交给客户端后再依靠 UI 隐藏。
- 不为战争题材向 Runtime 添加专用字段或按 `worldId` 分支。
- 不用模型即时生成权威地图拓扑；模型只能解释已经投影的可见节点和线索。
- 不让建议按钮自动提交行动、自动选择“最佳路线”或显示模型无法可靠估计的成功率。
- 不在本变更中重写全部十个战争场景；首个实现以开场三个阶段为接受切片，再按相同规则迁移余下内容。

## Decisions

### 1. 使用已发现节点图，而不是战术地图

世界包声明稳定的探索节点、连接和场景内可感知要素。节点表示可以被玩家识别和记忆的地点；要素表示当前场景中的对象、出口、危险迹象或环境线索。地图只投影玩家已经获知的节点和连接。

节点具有四种玩家可见状态：

- `VISITED`：玩家曾经到达；
- `DISCOVERED`：知道具体地点及可达关系，但尚未到达；
- `RUMORED`：只知道模糊名称或方向，不显示精确路线；
- `BLOCKED`：知道地点或路线存在，但当前明确不可通行。

完全未知节点没有玩家可见状态，也不会出现在 Presentation 中。状态允许从信息较少向信息较多升级，不能因一次普通场景切换倒退；路线重新封锁通过独立的动态可达状态表达。

选择节点图而非格子图，是因为当前产品的核心是自然语言意图、场景级时间和事件推进。节点图足以提供方向感和规划感，同时不要求引擎模拟米级空间。

### 2. 探索知识由通用规则模块和类型化事件维护

新增可选的题材无关探索能力，概念上包含：

```text
ExplorationDefinition
├── nodes[]          稳定 DefinitionId、显示名、短说明
├── connections[]    起点、终点、玩家可见方向/耗时/危险摘要
└── affordances[]    所属场景、类型、显示名、可见描述

ExplorationState
├── knownNodes
├── knownConnections
└── knownAffordances
```

发现变化通过类型化 Command/Event 进入 EventLog，例如：

```text
RevealExplorationKnowledgeCommand
                 ↓ validate IDs, actor, cause, visibility
ExplorationKnowledgeRevealedEvent
                 ↓ reducer
ExplorationState
```

进入场景、完成观察、NPC 揭示固定知识或行动结算都可以在同一权威批次中追加探索事件。UI、PM 和 NPC 只读取各自权限下的探索投影。随机结果和探索揭示保持同一 causation 链，回放不重新决定发现内容。

不把发现集合直接加进固定 `PlayerState`；它属于可选模块状态。旧世界不启用模块时继续使用现有场景体验。

### 3. 场景进入必须提供结构化局面，而非只靠一段文案

每个启用探索能力的可玩场景需要声明或投影以下玩家可见信息：

1. 当前地点和时间；
2. 最多三句的感官场景框架；
3. 当前目标或未解决问题；
4. 已知压力，例如时间、危险或资源约束；
5. 当前可见要素、附近 NPC 和已知出口；
6. 一个开放式收尾问题。

PM 的场景进入提示只能从该结构和已提交公开事件生成。正文可以有风格，但不得新增药房、路线、人物、物品或确定危险等未投影事实。

场景板是上述结构的持久摘要；聊天中的 PM 描述仍承担气氛与叙事。两者来自同一个 Presentation，避免互相矛盾。

### 4. 建议必须单独创作并声明可见依据

不再把全部动态工具出口无条件当作玩家建议。玩家建议独立声明：

```text
GuidanceSuggestion
├── id
├── sceneId
├── label
├── inputDraft
├── rationale?             为什么此刻值得考虑
├── tradeoff?              玩家能够合理估计的时间/危险/资源信息
├── groundingKnowledgeIds  地图节点、连接、要素或公开知识
├── target?                可选 Action/Activity/Travel/NPC/Draft 引用
└── tier                    EXAMPLE / HINT / NUDGE
```

投影建议前必须确认所有必要依据当前对玩家可见，目标若存在也必须当前合法。`DRAFT` 目标只预填自然语言，不承诺必然产生世界变化；其后仍由 PM 澄清或选择受限工具。

显示“高风险”“约十分钟”等取舍时，内容作者必须把对应信息绑定到可见压力、路线或规则成本。隐藏 DC、未揭示伏兵和精确结局概率不得进入建议。

### 5. 温和引导采用分层、可退让的提示梯

玩家偏好不写入 EventLog，也不改变世界规则：

- `NEWCOMER`：显示三类行动示例、理由和可感知取舍；首次使用地图和对话时提供短教程。
- `STANDARD`：显示精简建议标签，理由按需展开。
- `IMMERSIVE`：建议默认折叠，但地图、场景板和“需要提示”入口仍可使用。

所有模式都保留自然语言输入。新安装第一次开始 Run 默认 `NEWCOMER`；完成第一幕时建议切换 `STANDARD`，但由玩家确认，不能静默改变。

提示梯按顺序增加明确程度：

```text
场景可见事实
    ↓
可编辑行动示例
    ↓ 玩家主动“需要提示”
明确但不揭示结果的 Hint
    ↓ 连续两个已完成回合无事实、知识或场景推进
PM/NPC 的已创作 Nudge
```

停滞只依据已完成回合的公开证据判断，不分析玩家人格，也不因 Provider 失败、中断或仍在运行的回合累计。Nudge 是预先验证的表现内容，不产生新事实；若需要揭示线索，必须提交对应探索或 NPC 知识事件。

### 6. 关键线索不依赖一次成功检定

进入正确场景即可感知的核心要素自动公开。玩家明确观察正确对象时，推进所必需的核心线索不能因为一次随机失败永久消失；检定决定速度、代价、暴露或额外收益，而不是决定游戏是否还能继续。

每个关键阶段至少提供：

- 一条安全但耗时的思路；
- 一条快速但危险的思路；
- 一条依赖 NPC、物品或既有线索的思路。

它们可以共享底层 Action，但必须在取舍、事实或后续状态中至少有一项可观察差异。纯同义按钮不计为不同思路。

### 8. 战争开场接受切片按三个阶段设计

“前三个场景”按玩家体验解释为三个连续阶段：

1. 钟楼废墟建立局面和首次选择；
2. 成功/代价进入药房，失败进入火力压制，两者都形成可玩的分支场景；
3. 两个分支汇入旧排水渠，在 NPC 价值冲突中选择下一条长期路线。

这需要覆盖四个稳定 Scene ID，但玩家一次 Run 只经历其中三个。保留既有 ID，避免用题材分支改变 Runtime。

#### 阶段一：钟楼废墟

PM 首次描述：

> 炮声刚刚停下，灰尘正从钟楼残骸间落下。街对面的绿色十字招牌已经断了一半，药房卷帘门留着一道能钻进去的缝；西侧巷口还能看见通往旧水塔的路牌。玛拉腿上的伤口仍在流血，托马斯守着北侧缺口，说巡逻队很快就会回来。你们需要补给和离城路线——你准备先了解局面，还是立刻行动？

初始地图：

```text
旧水塔方向（RUMORED）
        │ 路线未知
【钟楼废墟】── 临街药房（DISCOVERED）
        │
北街（BLOCKED：巡逻风险）
```

初始示例：

- “我先观察街道和能提供掩护的地方。”——低风险，可能消耗时间；
- “@玛拉 你的伤势怎样？你知道附近的安全路线吗？”——可能获得人物线索；
- “趁街上安静，穿过街道进入药房。”——可能获得药品，暴露风险较高。

观察会自动给出肉眼可见的核心信息；检定只决定是否额外发现更安全的掩护、是否耗时或是否惊动巡逻。玛拉只能通过公开知识事件确认北路封锁和避难所线索。托马斯对水塔的地图仍可保留，不因地图 UI 泄露。

#### 阶段二 A：被洗劫的药房

PM 场景描述：

> 你钻进卷帘门，鞋底碾过碎玻璃。大部分药柜已经空了，但柜台后有一只锁住的红色急救箱；后墙的服务门下方吹进潮湿冷风，门外车辆的怠速声正在靠近。玛拉按住伤口，让你决定是快速撬箱、先找退路，还是让她辨认真正有用的药。

地图更新：药房升级为 `VISITED`；服务门只作为当前可见要素，检查后才能揭示通向排水渠的连接。

三种思路：

- 快速撬箱：快、噪声大，检定影响伤势或巡逻压力；
- 先检查后门：慢，但自动揭示排水渠退路；
- 请玛拉辨认药品：需要对话和她的参与，减少无用搜寻并影响关系。

核心急救物资不会因为一次失败永久消失。失败可以意味着只拿到部分物资、暴露行踪或被迫提前撤离；结果仍进入排水渠或配给站，不返回“再试一次”死循环。

#### 阶段二 B：巡逻队火力下

PM 场景描述：

> 你刚离开钟楼阴影，北街便亮起枪口火光。翻倒的电车挡住了第一轮射击，托马斯在车轮后发现一道通往排水渠的破口；左侧烟尘能遮住视线，但绕过去会多花时间。药房就在另一侧，却已经无法安全靠近。你要跟着托马斯冲向破口、借烟尘迂回，还是制造声响把火力引开？

地图更新：北街保持 `BLOCKED`，火力区成为当前 `VISITED` 节点，药房连接标为暂时不可达，排水渠成为 `DISCOVERED`。

三种思路：

- 跟托马斯冲刺：最快、风险最高；
- 借烟尘迂回：耗时但降低直接暴露；
- 使用物品或环境制造声响：依赖现有资源，可能保护同伴或改变关系。

失败推进到拘留或带伤进入排水渠，不能只显示“行动失败，请重试”。

#### 阶段三：旧排水渠岔口

PM 场景描述：

> 铁梯在你们身后发出最后一声震响，巡逻队的脚步被厚重井盖隔开。潮湿的渠洞分成两条：左侧墙上有学校避难所留下的白色布条，右侧生锈管道通向旧水塔方向。玛拉想先去照顾避难所的伤员；托马斯坚持水塔里的旧地图能绕开检查站。你可以继续追问、检查两条路留下的痕迹，或者选择相信其中一人。

地图更新：排水渠 `VISITED`，学校避难所和旧水塔均为 `DISCOVERED`，但各自的危险只显示玩家已经观察或被告知的部分。

此阶段第一次明确展示价值选择：救助幸存者可能换取车队频率，水塔路线可能获得涵洞地图。两条路线都有效，不标记推荐答案。

### 9. 十回合新手文字试玩

下面的脚本是验收示例，不要求模型逐字复述；它规定每轮玩家知道什么以及为何能看到下一项建议。

1. PM 进入钟楼，公开药房招牌、水塔路牌、附近 NPC 和巡逻压力；地图只出现三个已知条目。
2. 玩家选择“观察街道”；PM 公开北街履带声和一段可用掩护，时间推进但不要求为明显事实掷骰。
3. 玩家 `@玛拉` 询问伤势；玛拉公开北路封锁和避难所持有无线电频率，地图增加“学校避难所（RUMORED）”。
4. 玩家决定穿过街道；规则完成风险检定并以代价成功进入药房，PM 明确伤势或时间代价。
5. 玩家检查后门；公开潮湿气流和排水渠铁梯，药房至排水渠连接变为 `DISCOVERED`。
6. 玩家请玛拉判断药品；NPC 只依据公开药柜和自己的知识回应，并让急救箱价值变得明确。
7. 玩家选择快速撬箱；结算获得部分药品并提高巡逻压力，地图不提前出现检查站或车队。
8. 玩家从后门撤入排水渠；场景进入事件把排水渠设为 `VISITED`，PM 介绍两条可见岔路。
9. 玩家分别询问玛拉和托马斯；两人公开各自路线的目标与已知筹码，不替玩家决定。
10. 玩家选择避难所路线；结算路线风险并进入下一阶段，主持历史、地图、时间、药品、关系和场景在保存/恢复后完全一致。

替代回归路线把第 4 回合改成失败：玩家进入火力压制，经过“观察掩护—询问托马斯—选择撤离方式”三个回合后仍汇入排水渠；任何提示都不得提到尚未公开的急救箱、涵洞地图、检查站或结局条件。

### 10. 验证以玩家可见证据为核心

世界包校验增加以下规则：

- 节点、连接、要素和建议 ID 唯一且引用闭合；
- 初始场景必须存在场景框架、目标、压力或明确的无压力状态，以及至少两个可理解的行动思路；
- 建议的依据必须能在其显示条件下公开；
- 建议目标若为 Action/Activity/Travel/NPC，显示时必须合法；
- 关键节点不能只由一个可永久失败的线索入口到达；
- 所有可达活跃场景仍需失败推进或明确终局；
- Presentation 快照不得包含未知节点、连接、要素或私有 NPC 知识；
- `war-survival` 与 `station-ai` 使用同一探索模块和投影路径。

自动测试包括纯验证器测试、Command/Event/Reducer 回放、投影泄密测试、Fake PM 建议测试、十回合旅程、存档恢复和三端布局编译。真人可用性测试重点记录“玩家是否在 30 秒内说出至少两个合理行动”，而不是只记录是否点击了预设按钮。

## Risks / Trade-offs

- [地图让玩家只追着节点点击，削弱自由输入] → 地图节点只打开信息或预填旅行意图；聊天输入始终是主操作，未知对象仍可通过自然语言调查。
- [作者为了通过验证把所有地点一开始都公开] → 对关键路线要求多来源发现，但不要求初始全公开；内容审查检查迷雾和信息节奏。
- [建议依据过细导致创作成本升高] → 提供作者工具从场景要素生成候选依据，但安装前仍做静态闭包和可见性验证。
- [停滞检测误把角色扮演对话当作卡关] → 只在连续两个回合无新事实且玩家未关闭帮助时轻量突出“需要提示”，不自动推进或打断对话。
- [地图状态与 EventLog 不一致] → 发现只能由类型化事件更新；客户端不持久化独立地图真相。
- [内容版本升级破坏旧存档] → 保留旧内容版本用于旧 Run；新目录只创建新版 Run，绝不把新拓扑静默套到旧 EventLog。
- [移动端地图遮挡聊天或键盘] → 使用互斥的全屏/Sheet 展示，关闭后恢复原滚动位置和输入草稿。
- [展示风险标签泄露隐藏规则] → 风险和耗时只允许引用玩家已知信息或固定公开成本，不显示隐藏 DC 和结局概率。

## Migration Plan

1. 以可选、带版本的探索定义和模块状态扩展世界包；旧包未声明时维持原行为。
2. 先在测试夹具和 `station-ai` 的最小节点样例验证题材无关性，不改变其剧情路线。
3. 为战争内容发布新内容版本，保留既有 Scene/Action/NPC ID，并为旧 Run 保留旧版本解析入口。
4. 新 Run 使用重新创作的开场三个阶段；旧 Run 不注入伪造的发现事件，也不静默迁移地图状态。
5. 分别启用场景板、只读地图和新建议投影；出现严重问题时可隐藏地图/新建议 UI，同时保留权威事件和旧版本内容继续恢复。
6. 完成十回合自动旅程、Android 真机窄屏、Desktop 横屏和 iOS 编译门禁后，再迁移战争剧本剩余场景。

## Open Questions

- 移动端地图最终采用全屏页还是半高 Sheet，需要用真实设备比较键盘、单手操作和长地点名表现；规格只要求两者之一满足可用性。
- 玩家完成第一幕后是否弹出引导强度切换提示，还是只在设置中提供，需要首次真人试玩验证打断感。
- 路线风险使用离散标签还是只用自然语言，首个切片先采用作者提供的自然语言摘要，不承诺通用数值概率。
