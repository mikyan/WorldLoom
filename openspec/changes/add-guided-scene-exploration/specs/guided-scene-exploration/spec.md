## ADDED Requirements

### Requirement: 世界包必须声明可验证的场景探索图
启用场景探索能力的世界包 SHALL 使用稳定且带命名空间的 ID 声明地点节点、节点连接和场景内可感知要素，并 SHALL 通过静态校验保证引用闭合、所属场景合法且初始可见内容可达。

#### Scenario: 世界包包含悬空地图连接
- **WHEN** 一个连接引用未声明的起点或终点节点
- **THEN** 世界包验证失败并返回包含连接路径与无效 ID 的诊断

#### Scenario: 旧世界未启用探索能力
- **WHEN** 一个兼容旧世界没有声明探索定义或启用探索模块
- **THEN** Runtime 继续加载原场景体验且不伪造地图节点或发现事实

### Requirement: 已发现地图必须只来自权威玩家可见事实
系统 MUST 通过类型化 Command/Event/Reducer 更新已知节点、连接和要素；Presentation MUST 只包含当前玩家已经到达、观察到或通过公开对话获知的探索知识，完全未知内容不得交给 UI 后再隐藏。

#### Scenario: 玩家观察到药房招牌
- **WHEN** 已提交事件向玩家公开药房节点和从当前场景可辨认的方向
- **THEN** 地图投影显示药房为已发现地点并保留对应事件证据

#### Scenario: 世界包包含隐藏涵洞
- **WHEN** 涵洞节点尚未被任何玩家可见事件揭示
- **THEN** 地图、场景板、PM 上下文、快捷建议和公开回放均不包含涵洞名称、连接或描述

#### Scenario: 保存后恢复 Run
- **WHEN** 应用从 EventLog 和兼容 Snapshot 恢复包含探索事件的 Run
- **THEN** 已知节点状态、连接、要素和当前场景与停止前一致且不重新运行随机发现

### Requirement: 每次场景进入必须建立可行动的局面
启用探索能力的活跃场景 SHALL 向玩家提供当前位置、感官框架、当前目标或问题、压力或明确的无压力状态、附近角色、已知出口和开放式行动询问；明显可感知的核心信息 MUST 无需检定即可获得。

#### Scenario: 玩家首次进入钟楼废墟
- **WHEN** 场景进入投影完成
- **THEN** 玩家能够从 PM 描述和场景板得知药房存在、附近 NPC、巡逻压力和当前补给目标，而无需查看隐藏世界定义

#### Scenario: 明显出口需要观察检定
- **WHEN** 内容把推进所必需且肉眼明显的唯一出口配置为可能永久失败的随机发现
- **THEN** 世界包验证拒绝该内容或要求另一个无需永久成功的推进来源

### Requirement: 玩家建议必须与规则出口分离并具有可见依据
系统 SHALL 仅显示独立声明且当前满足可见依据的建议，不得把全部可用 Action、Activity 或 Travel 自动视为适合玩家的建议。建议 MAY 引用合法工具目标或只预填自由意图，但 MUST NOT 自动提交。

#### Scenario: 药房尚未被公开
- **WHEN** 一个建议文本或理由提到药房但其依据节点和要素对玩家不可见
- **THEN** 建议不进入 Presentation，验证器或运行诊断指出缺少可见依据

#### Scenario: 玩家选择观察范例
- **WHEN** 玩家点击一个 `DRAFT` 类型的观察建议
- **THEN** UI 只把自然语言草稿放入输入框并允许玩家编辑或取消，不写入 EventLog

#### Scenario: 建议引用已关闭的路线
- **WHEN** 建议目标是当前状态下不可用的 Travel 或 Action
- **THEN** 建议不会显示，即使它的地点依据仍然可见

### Requirement: 风险与取舍提示不得泄露隐藏规则
建议 MAY 展示角色能够合理估计的时间、资源或危险摘要，但 MUST 绑定已公开压力、固定公开成本或可见环境证据；隐藏检定难度、伏兵、秘密奖励和结局概率不得进入玩家投影。

#### Scenario: 玩家看见巡逻队接近
- **WHEN** 已公开事件表明穿越街道会暴露于巡逻风险
- **THEN** 对应建议可以显示“暴露风险较高”，但不显示隐藏 DC、随机表或失败将进入哪个场景

### Requirement: 温和引导必须分层且受玩家控制
系统 SHALL 提供新手、标准和沉浸引导强度；所有强度 MUST 保留自由输入、地图和主动请求提示的入口。教程、建议、提示与停滞救援 MUST 支持跳过或收起，且不得改变权威规则或替玩家行动。

#### Scenario: 新玩家开始第一个 Run
- **WHEN** 玩家尚无已保存的引导偏好
- **THEN** UI 使用新手层展示少量带理由的可编辑示例，并允许立即切换或跳过

#### Scenario: 沉浸模式请求提示
- **WHEN** 沉浸模式玩家主动点击“需要提示”
- **THEN** 系统显示当前场景经过可见性验证的 Hint，而不会重新启用全部常驻新手教程

#### Scenario: 连续对话没有事实推进
- **WHEN** 玩家进行角色扮演对话且没有明确请求帮助
- **THEN** 停滞检测最多突出可选提示入口，不自动提交动作、不强制 NPC 打断且不把对话判为错误

### Requirement: 核心探索线索必须失败推进
关键剧情节点 MUST 至少具有一个不会因单次随机失败永久消失的发现来源。需要检定的观察或行动 SHALL 让成功度影响时间、代价、暴露或额外收益，而不得让活跃 Run 因遗漏唯一核心线索而无合法推进方式。

#### Scenario: 核心线索检定失败
- **WHEN** 玩家在正确场景用合理方式寻找推进所需的核心线索但检定失败
- **THEN** 玩家仍获得最小推进信息，同时系统记录可审计的时间、资源、危险或叙事代价

### Requirement: 地图与场景板必须适配桌面和移动端
桌面端 SHALL 保持聊天为视觉中心并通过可关闭抽屉或等效紧凑交互显示地图；移动端 SHALL 在安全区提供场景入口，并通过不与输入键盘争抢高度的全屏页或 Sheet 显示地图。现有紧凑角色清单不得因地图永久增高或扩宽。

#### Scenario: 移动端键盘打开
- **WHEN** 玩家正在编辑自然语言行动且软键盘可见
- **THEN** 地图不会覆盖发送控件，关闭地图后聊天滚动位置和输入草稿保持不变

#### Scenario: 桌面端关闭地图抽屉
- **WHEN** 玩家收起场景地图
- **THEN** 中央聊天恢复可用宽度，右侧角色清单保持原有紧凑布局

### Requirement: PM 与 NPC 必须共享相同的探索可见性边界
PM 上下文 SHALL 获得玩家可见的场景框架、探索知识和合法建议；NPC 上下文 SHALL 只获得该 NPC 感知或已知的相应子集。模型生成的叙述不得独立创建地图事实。

#### Scenario: PM 提到未知地点
- **WHEN** Provider 正文引入一个未投影的具体地点并且没有工具事件支持
- **THEN** 该正文不能使地点出现在地图、建议或权威状态中，后续 PM 上下文仍以投影事实为准

#### Scenario: NPC 私有路线未揭示
- **WHEN** NPC 知道一条私有路线但尚未通过获准知识事件公开
- **THEN** 玩家地图和其他 NPC 上下文都不包含该路线
