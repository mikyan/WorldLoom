## Context

迭代 16–25 已建立 `Intent → Command → Event → Presentation` 竖切、持久化 GM Turn、NPC/Behavior 调度、一个完整战争短剧本和公开回放。当前产品缺口主要位于权威事件之外的体验层：GM 输出只保存在单个 Turn 行且没有历史查询，进程恢复后 UI 无法重建主持对话；玩家不能显式选择并交谈场景 NPC；主持人长期记忆尚未进入 GM 上下文；卡关、自动存档和恢复状态也缺少明确反馈。

仓库已有 TXT/EPUB 解析和确定性草稿生成基础，但它们不能在手写世界的主持体验尚未形成稳定产品契约时成为主路径。本变更因此先补完 26–33，再让 34–35 复用同一可玩世界校验和沙箱运行边界。

## Goals / Non-Goals

**Goals:**

- 让玩家在重启后看到同一 Run 的完整公开主持回合，并安全处理澄清、失败和中断。
- 提供玩家到指定 NPC 的公开对话链，同时维持 NPC Session、记忆和知识的严格隔离。
- 让 GM 使用可恢复的增量连续性上下文，但不把摘要或模型文本变成世界事实。
- 用声明式引导和明确的保存状态减少首局卡关，并把 `station-ai` 提升为第二个完整内置短剧本。
- 将来源识别与草稿试玩限制在可恢复工作区和隔离 Run 中，只有通过 `playable-world/v1` 的草稿才可试玩或安装。

**Non-Goals:**

- 不把 GM/NPC 的最终模型正文写入 EventLog 或当作规则事实。
- 不允许对话或草稿绕过 Tool Gateway、CommandValidator、WorldEngine 与事件追加。
- 不在本变更中实现任意脚本、联网素材抓取、自动发布社区世界或无审核的一键生成。
- 不承诺真实 Provider 输出确定性，也不以生成世界替代两个内置世界的回归。

## Decisions

### 1. GM Turn 历史是可恢复的公开表现记录，不是客观事实

扩展 `GameTurnStore` 的 Run 级分页读取，并为 `GameTurn` 增加版本化公开输出类型、证据序列范围和恢复元数据。UI 将玩家输入、澄清、已完成叙事和失败提示组合为主持记录；EventLog 仍是状态与规则事实的唯一权威。

选择独立 Turn 历史而非把每段叙事包装为 `GameEvent`，因为模型措辞不是确定性世界事实。公开回放可选择附带经过过滤的 Turn 表现，但重放验证只验证其证据序列引用，不用正文重建状态。

### 2. 中断恢复按事实提交边界分类，不自动重放模型

恢复器扫描 `ACCEPTED/RUNNING` Turn：若 EventLog 序列未前进，标记可安全重试；若已有事件，标记“事实已提交、叙事待恢复”，由一个只读补叙述请求重新读取公开事实，禁止工具调用。原 Turn 永不再次执行工具，新请求使用新的 TurnId 并引用旧 TurnId。

这比自动重试原 Turn 更保守，可避免 Provider 超时后重复扣资源或推进场景。

### 3. 定向 NPC 对话先记录玩家公开发言，再调度单个 NPC

新增带长度限制的 `AddressNpcCommand/Event`，只允许当前场景公开参与者作为目标。事件记录玩家公开表达和目标 NPC，不记录模型私有正文；提交后使用稳定 `EventId + NpcId` 工作项唤醒且只唤醒目标 NPC。NPC 仍必须用 `npc.speak`/`npc.act` 发布响应。

相比由 GM 提示词隐式猜测交谈对象，类型化对话能稳定恢复、审计权限并避免唤醒无关 NPC。

### 4. 知识揭示使用显式 ID，不从自然语言反推事实

NPC Profile 的私有知识升级为版本化知识条目，包含稳定 ID、私有正文和可选公开摘要。NPC 工具只能提交白名单 `revealKnowledgeIds`；验证成功后产生公开揭示事件并更新 NPC 自己的情节记忆。公开提示与 GM 上下文只看到已揭示摘要，不能读取剩余私有正文。

### 5. GM 连续性通过 AgentMemoryStore 的专用 GM 分区组装

每个完成 Turn 生成候选公开情节记忆，异步压缩器按冻结事件/Turn 范围发布检查点。`GmContextProjector` 组合最后有效检查点、有限最近 Turn 和当前权威 Presentation；检查点失败时继续使用旧检查点与原始尾部。

GM 和每个 NPC 使用不同稳定 AgentId，因此 SQL 存储、召回和日志都不能跨分区读取。

### 6. 引导来自世界包 Definition，并由通用可达性规则兜底

世界包可为场景声明教程步骤、提示和行动分组；Runtime 仅解析通用 Schema。若当前没有可用行动、活动或路线但尚未结束，应用层根据已验证的失败推进出口生成通用恢复建议并记录诊断，不按 worldId 分支。

### 7. 自动存档代表持久化证据，不伪造保存进度

EventStore/TurnStore 成功提交后更新 Run 目录的 `lastPersistedSequence`、`lastTurnId` 和状态时间戳。UI 只在这些持久化写成功后显示“已保存”；失败时展示可重试诊断。快速继续必须重新校验世界版本、EventLog 连续性和 Snapshot，而不是复用内存状态。

### 8. 第二内置世界必须达到与战争世界相同的可玩契约

`station-ai` 将获得完整场景图、多路线、NPC、资源、Behavior 和至少三个结局，并进入内置目录。所有新增能力通过两个世界的同一契约测试证明没有题材分支；内容平衡只改世界包配置。

### 9. 识别工作区与试玩沙箱是可取消、可恢复、隔离的边界

识别任务保存来源哈希、解析检查点、片段范围、诊断和草稿版本，不保存 Provider 密钥。草稿验证先运行 Schema/引用/模块/Behavior/可达性检查；通过后才可复制到独立 Sandbox EventStore 创建临时 Run。沙箱事实不得进入正式 Run 目录，安装操作使用内容寻址版本并原子发布。

### 10. 每轮独立兼容、迁移和提交

26–35 每轮只引入本轮所需 Schema；SQLDelight 迁移逐号追加并保留迁移验证数据库。每轮运行受影响模块测试、OpenSpec strict validation、`git diff --check`，再使用英文 Conventional Commit 推送 `main`。第 35 轮运行全仓候选门禁。

## Risks / Trade-offs

- [Turn 历史与 EventLog 分离后可能出现悬空证据引用] → 加载时校验证据序列不超过 EventLog，损坏 Turn 只隔离表现记录，不篡改状态。
- [补叙述仍可能产生与事实不一致的文字] → 补叙述模式禁用工具、只投影指定事件范围并要求空/越界结果失败。
- [玩家自由文本可能包含敏感信息] → 限长、日志脱敏，公开导出默认明确标注玩家输入；私有导出仍需显式选择。
- [显式知识 ID 增加世界作者负担] → 提供校验诊断与兼容转换，但不以自然语言猜测揭示状态。
- [空间站内容扩大回归时间] → 使用黄金路线和静态可达性测试，保持通用 Runtime 不增加题材分支。
- [识别/沙箱扩展过早抢占主持体验] → 任务依赖固定为 34 在 33 完成后、35 在 34 完成后，门禁始终包含两个手写世界。

## Migration Plan

1. 先扩展 Turn Store 与迁移，旧 Turn 按默认输出类型和已有序列范围读取。
2. 再追加 NPC 对话/知识 Event Schema；旧世界 Profile 在未声明知识 ID 时仍可加载但不能声明揭示事实。
3. 接入 GM 记忆、引导和 Run 持久化元数据，所有字段提供版本化默认值。
4. 升级 `station-ai` 内容版本并保留旧 Run 的固定内容版本拒绝/迁移诊断。
5. 最后增加识别工作区与沙箱表；失败或回滚时可删除草稿工作项，不触碰正式 EventLog。

## Open Questions

- 真实 Provider 的补叙述措辞是否需要可选本地二次一致性检查，将依据第 27–30 轮试玩证据决定。
- 玩家输入是否进入默认公开回放，将先采用显式包含且可关闭的策略，并在第 35 轮隐私审计中复核。
- 草稿安装签名和社区分发不属于本变更，后续需要单独 ADR。
