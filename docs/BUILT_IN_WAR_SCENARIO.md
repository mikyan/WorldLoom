# 《灰烬中的车队》内置短剧本

文档状态：Content v1<br>
预计时长：约 60 分钟

## 1. 试玩目标

这个内置世界用于证明 Worldloom 能在不依赖剧本识别和自动世界生成的前提下，完成一次由 Agent 主持、确定性引擎裁决的单人跑团：

```text
选择内置世界 → 固定角色建角 → 主持人呈现场景
→ 玩家自然语言或快捷行动 → 检定/时间/活动/旅行
→ Behavior 与 NPC 公开响应 → 结局 → 回放
```

试玩内容当前固定为 `contentVersion = 1`，并通过题材无关的 `catalogPriority` 排在内置目录首位。此次引导改版保留既有 Scene、Action、NPC、Objective 与 Ending ID，在同一兼容内容版本内增加带默认值的探索定义；已存在 Run 不会被强制注入发现，恢复仍完全以其 EventLog 为准。若后续修改稳定拓扑或既有结果语义，必须发布新的 `contentVersion` 并同时保留旧内容解析入口。内容和规则均来自世界包；Runtime、主持人和共享 UI 不按 `worldId` 或 `war.*` 私有键分支。

新 Run 的钟楼开场会在任何药房建议前公开绿色十字招牌、相对方向、水塔模糊路牌、附近同伴与巡逻压力。节点地图随后只按已提交发现更新：药房成功/代价路线和受火力压制的失败路线都能汇入排水渠；急救箱不会出现在火力分支，涵洞、检查站和结局条件在对应事实公开前也不会进入地图、建议或主持上下文。地图 UI 可作为回滚开关隐藏，但权威探索事件继续保留，以免破坏恢复与回放。

## 2. 内容结构

- 10 个关键场景：钟楼废墟、药房、火力封锁、排水渠、避难所、水塔、配给站、检查站、拘留棚和撤离车队；
- 12 个可检定行动，每个失败结果都进入替代场景或明确结局；
- 10 个公开目标、5 段任务链、2 个进度钟和 3 个结局；
- 等待、休息、搜寻、治疗、3 条旅行路线和 2 个世界时间触发；
- 5 类物品、3 类状态、2 条角色关系和 3 个可恢复 Behavior；
- 玛拉与托马斯两名场景 NPC，具有独立身份、目标、秘密、感知白名单、Session 和公开动作白名单。

## 3. 主持人与 NPC 边界

主持人只接收玩家可见事实、当前场景描述、公开参与者、动态可用行动、公开事件和预算。主持人选中的行动仍必须经过 Tool Gateway、类型化 Command、Validator、WorldEngine、EventLog 和 Reducer；叙述不能先于事实改变世界。

玛拉的 `war.knowledge.mara.north-blockade` 与托马斯的 `war.knowledge.tomas.culvert-map` 分别保存北侧封锁、避难所频率和涵洞路线的私有正文。两人的私有知识不会互相投影，也不会进入主持人上下文、玩家 Presentation 或公开重放。NPC 只能在自己的 `npc.speak` 白名单中提交知识 ID；Runtime 使用世界包固定公开摘要生成 `NpcKnowledgeRevealedEvent`，后续主持人和公开回放只能看到该摘要。

玩家也可以从当前场景的可交谈角色列表选择玛拉或托马斯。`npc.address` 只暴露当前场景允许交互的 NPC ID，玩家发言形成 `NpcAddressedEvent` 后，仅由 `EventId + targetNpcId` 对应的角色工作项消费；未选择角色的对话记忆不会改变。重复幂等键不会追加第二条发言或再次唤醒角色。

定向玩家发言、该角色的公开回应和知识摘要会形成带来源 EventId 的公开情景记忆，但仍存放在同一 NPC 的 AgentId 分区。重复揭示同一知识不会追加第二个事件，其他 NPC 的知识 ID 会在 Tool Gateway 与 CommandValidator 两层拒绝。

## 4. 黄金路线

| 路线 | 主要选择 | 结局 |
|---|---|---|
| 成功 | 药房 → 玛拉/避难所 → 名单交涉 → 车队 | 带着希望撤离 |
| 代价成功 | 药房 → 托马斯/水塔 → 涵洞 → 车队 | 付出代价后幸存 |
| 失败 | 搜寻暴露 → 火力封锁 → 拘留棚 | 落入巡逻队之手 |

三条路线使用脚本化 2d6 随机记录从建角运行到结局，随后从 EventLog 重放并比较完整最终 Presentation。测试同时覆盖超量使用库存、场景外非法行动、SQLDelight 存档恢复、NPC 私密上下文和 `station-ai` 跨题材契约。

## 5. 当前范围

这是用于验证核心游玩闭环的一次撤离短篇，不等同于设计文档中规划的 300～1000 世界日长期战役。后续先完善游玩界面、Run 目录、继续游戏与公开回放，再在同一世界包边界内扩展长期内容；TXT/EPUB 识别和自动世界生成不作为本短篇的运行前提。
