# Worldloom 游戏页面风格规范

状态：Draft<br>
版本：0.1<br>
适用范围：`shared:ui-game` 及 Android、iOS、Desktop 的共享游戏体验<br>
目标：让首页、建角、游玩、存档、设置与内容工作区具有同一产品身份，同时允许不同世界保留自己的气氛。

## 1. 规范定位

本规范是 Worldloom 共享 UI 的视觉与交互基线，负责回答以下问题：

- 页面如何体现“织境”品牌，而不是退化成通用 Material 表单；
- 不同信息密度的页面如何保持同一套层级、组件和反馈语言；
- 世界包可以改变哪些表现，哪些语义颜色与交互规则必须稳定；
- Compact、Medium 与 Expanded 布局如何复用同一信息架构；
- 新页面如何验收，避免继续增加局部颜色、尺寸和一次性组件。

本规范不替代 `PresentationDefinition`、世界包或规则模块。UI 仍只读取应用层只读投影，不根据 `worldId`、题材名称或具体 DefinitionId 分支，也不把视觉状态当作世界事实。

## 2. 设计主张

### 2.1 核心意象

默认视觉语言为：

> 幽暗织物承载世界，金色丝线标记命运，低饱和场景提供气氛，清晰的信息层保证规则可信。

界面应同时具备四个特征：

1. **沉浸但不遮蔽**：场景图服务叙事，文字、操作和系统反馈始终清楚。
2. **克制但不寡淡**：常态使用低对比背景和细边框，金色只用于焦点与关键行动。
3. **有机但不随意**：梦茧、丝线和柔和渐变用于品牌节点；表单、列表和审计内容仍使用严格网格。
4. **动态但不躁动**：平时只保留轻微呼吸与淡入，规则结果、揭示和转场才集中释放动效。

### 2.2 三种体验密度

所有页面归入一种密度，而不是自行决定视觉强度：

| 密度 | 适用页面 | 原则 |
|---|---|---|
| 沉浸型 | 首页、梦境选择、结局 | 大面积场景、少量文字、单一主行动 |
| 聚焦型 | 角色创建、存档、设置、识别与安装 | 中等密度、明确步骤、受控内容宽度 |
| 游玩型 | 叙事对话、场景地图、角色与目标 HUD | 高信息密度，但始终保持“场景 → 叙事 → 行动”的主次顺序 |

三个密度共享颜色角色、字阶、间距、按钮、反馈和动效节奏。沉浸型可以更具装饰性，游玩型必须更克制。

## 3. 表现分层与世界边界

```text
固定品牌层        深色基底、命运金、字体层级、组件语义、动效节奏
      ↓
页面体验层        沉浸型 / 聚焦型 / 游玩型布局与密度
      ↓
世界气氛层        背景、头像、插图、公开标题与 Presentation 绑定
      ↓
语义状态层        成功、警告、危险、禁用、私密、选中、焦点
```

约束如下：

- 品牌色、错误色、焦点态和可访问性规则由共享 UI 固定，世界包不能覆盖；
- 世界包可以通过已验证的 `backgroundAssetId`、`avatarAssetId` 和公开文案改变气氛；
- 当前版本不允许世界包提交任意颜色、字体、Shader 或 UI 代码；
- 若后续增加 `PresentationPalette`，只能填写受限的气氛角色，并在加载时验证对比度与回退值；
- 未知或缺失资产必须回退到通用织物背景、首字头像和标准品牌色；
- 成功、危险、私密与禁用状态不能只靠世界插图或颜色表达。

## 4. Design Token

### 4.1 颜色

下表使用 RGB 十六进制；带透明度的表面在实现中使用同名基础色与统一 alpha，禁止页面重新复制近似颜色。

| 角色 | 建议值 | 用途 |
|---|---:|---|
| `canvas` | `#0B0E10` | 无场景图时的全局背景 |
| `surface` | `#15191B` | 普通面板、卡片、输入区 |
| `surfaceStrong` | `#111518` | HUD、模态框、需要更强可读性的面板 |
| `surfaceRaised` | `#202527` | 悬浮、选中或可交互条目 |
| `scrim` | `#050708` / 70% | 模态遮罩和背景压暗 |
| `borderSubtle` | `#E8D7AE` / 22% | 普通细边框与分隔 |
| `borderFocus` | `#E2BD72` / 72% | 键盘焦点、选中与当前对象 |
| `brandPrimary` | `#E2BD72` | 命运金、主行动、PM、关键标题 |
| `onBrandPrimary` | `#21170B` | 金色实心控件上的文字与图标 |
| `narrativeNpc` | `#80B8B3` | NPC、关系与对话对象 |
| `narrativePlayer` | `#D5A75B` | 玩家发言与玩家侧焦点 |
| `textPrimary` | `#F3EFE5` | 标题、正文、主要数值 |
| `textSecondary` | `#B9B7B0` | 补充说明、元数据 |
| `textMuted` | `#8E8C86` | 非关键时间戳与占位信息 |
| `info` | `#AAA4C8` | 未确定、传闻、一般信息 |
| `success` | `#79B99B` | 已完成、连接成功、已保存 |
| `warning` | `#D9A85C` | 风险、待修复、资源压力 |
| `error` | `#E47D6D` | 失败、损坏、不可恢复操作 |

使用规则：

- 一个视区最多有一个金色实心主行动；其余使用描边、弱底色或文字按钮；
- 金色不是普通装饰色，不能让每个标题、边框和按钮同时变金；
- 场景背景上必须叠加渐变或实色遮罩，正文不能直接压在高频图像上；
- 普通边框只提供层级，不承担文字可读性；
- 语义色必须同时配合图标、标签或状态文案。

### 4.2 字体与字阶

在引入并验证可分发字体前，使用平台无衬线字体。装饰字体只允许用于品牌标题和梦境名称，正文、数值、输入与审计信息不得使用装饰字体。

| 角色 | 字号 / 行高 | 字重 | 用途 |
|---|---:|---:|---|
| `display` | 32 / 40 sp | 700 | 首页品牌、结局标题 |
| `pageTitle` | 24 / 32 sp | 700 | 页面标题 |
| `sectionTitle` | 18 / 26 sp | 600 | 场景、任务、表单分组 |
| `body` | 15 / 23 sp | 400 | 叙事、说明与主要表单内容 |
| `bodyCompact` | 14 / 20 sp | 400 | HUD、紧凑卡片与按钮 |
| `label` | 12 / 16 sp | 600 | 标签、说话者、状态名称 |
| `caption` | 11 / 16 sp | 400 | 时间、来源与辅助元数据 |

- 主要交互文字不得小于 12 sp；9–10 sp 仅可用于非必要装饰，默认不应出现；
- 长叙事正文保持 20–26 sp 行高，并限制单行长度；
- 数值使用等宽数字特性或稳定宽度，避免状态更新时跳动；
- DefinitionId、枚举名和序列化值不能直接展示给玩家。

### 4.3 间距、圆角与尺寸

基础间距阶梯：`4 / 8 / 12 / 16 / 24 / 32 dp`。

| 场景 | 规则 |
|---|---|
| 页面边距 | Compact 12–16 dp；Medium 16–20 dp；Expanded 24 dp |
| 同组内容 | 4–8 dp |
| 组件之间 | 12–16 dp |
| 大区块之间 | 24–32 dp |
| 控件圆角 | 6 dp |
| 卡片/面板圆角 | 12 dp |
| 对话与重要容器 | 12–16 dp |
| 模态框/Sheet | 16 dp |
| 茧、头像、状态点 | 50% 圆形或胶囊 |
| 最小可点区域 | Desktop 44×44 dp；触屏 48×48 dp |

细小的图标或头像可以小于最小可点区域，但外层命中区域必须满足要求。

### 4.4 表面与层级

界面最多使用四个视觉深度：

1. 场景或织物背景；
2. 内容表面；
3. 选中、悬浮或强信息表面；
4. 模态框、全屏地图或关键结果。

阴影只用于从背景中分离浮层。常规层级优先通过明度、遮罩和细边框表达；同一容器内禁止连续嵌套三层 Card。

## 5. 响应式布局

统一使用宽度断点，不再由每个页面独立猜测“手机或桌面”：

| 尺寸 | 宽度 | 布局策略 |
|---|---:|---|
| Compact | `< 720 dp` | 单列；次要内容使用全屏页或 Sheet；主行动靠近拇指区 |
| Medium | `720–1199 dp` | 主区 + 一个辅助区；地图、HUD 或目录按任务互斥 |
| Expanded | `≥ 1200 dp` | 主区 + 稳定 HUD；场景抽屉可按需成为第三列 |

高度小于 `620 dp` 时进入 Short 模式：压缩装饰留白、限制预览高度，但不缩小主要文字和命中区域。

通用规则：

- 所有页面尊重 safe drawing inset、键盘和窗口缩放；
- 聚焦型页面的正文最大宽度为 760 dp，设置/工作区最大宽度为 960 dp，不能在宽屏上把表单拉满；
- Desktop 游戏页 HUD 建议 288–320 dp，场景抽屉建议 288–320 dp，中央叙事区至少 480 dp；空间不足时先收起抽屉，再把 HUD 移为覆盖层；
- Compact 游戏页只常驻场景条、对话、建议和输入，地图与完整 HUD 不和软键盘争抢高度；
- 长对话、事件、角色、候选和存档列表必须惰性加载或分页；
- 切换地图、角色资料和设置时保留聊天滚动位置、输入草稿和当前选择。

## 6. 页面骨架

### 6.1 沉浸型页面

适用于首页、梦境选择与结局：

- 全屏使用一张主视觉，叠加统一遮罩；
- 首屏只呈现品牌、短叙事和一个行动组；
- 主行动不超过一个，次行动不超过三个；
- 重要信息放在清晰表面上，不能依赖画面中自带文字；
- Compact 以底部操作区为主，Expanded 可使用左侧或右侧留白。

沉浸型页面的视觉母版由全屏主视觉、梦茧式选择与织梦者叙事气泡组成；其颜色、按钮和面板统一使用共享 token。

### 6.2 聚焦型页面

适用于角色创建、存档、设置与识别：

```text
页面标题 / 返回 / 当前步骤
        ↓
说明或状态摘要
        ↓
主要内容表面（受控宽度）
        ↓
固定或清晰可见的操作区
```

- 背景可以保留低对比世界图或织物纹理，但表单表面必须稳定；
- 表单先显示玩家语言，再按需显示高级技术信息；
- 每个步骤明确“当前选择、剩余要求、确认结果”；
- 错误放在相关字段或操作区附近，不用页面底部孤立红字；
- 取消、删除、安装等不同风险操作必须在样式和位置上区分。
- 设置使用稳定的一级导航；Provider 与模型必须作为两个独立选项卡。Expanded 使用左侧导航，Compact 使用顶部等宽导航；切换选项卡时保留未提交的页内选择。
- Provider 选项卡使用纵向列表，一行对应一个来源并显示凭据状态；编辑区在当前行内展开，不使用横向卡片轮播。Provider 页只管理连接地址与凭据，不混入当前模型选择。
- 模型选项卡按“Provider → Model”顺序提供两个选择字段；模型列表从所选 Provider 获取，同时保留手工填写 Model ID 的兼容路径。只有明确应用后才切换运行时默认模型。

角色创建必须特别遵守：

- 不显示 Profile ID、DefinitionId、`TypedValue.toString()` 或内部模式名；
- Desktop 使用“选项/字段 + 角色摘要”双区，Compact 使用单列和可展开摘要；
- 固定角色、预设、点数分配和表单模式共享同一 Page Header、Field、Choice Card 和 Footer Action；
- 确认前展示人类可读的最终摘要，字段顺序由 Presentation 驱动。

### 6.3 游玩型页面

游戏页的权威视觉顺序固定为：

```text
当前场景与压力
       ↓
公开叙事与角色回应
       ↓
玩家行动与条件式判定卡
       ↓
可编辑的行动建议
       ↓
自然语言输入
       ↓
状态、目标、地图与审计详情
```

规则：

- 对话和输入始终是视觉中心；HUD、地图和时间线不能抢占主操作；
- 场景条始终显示地点、一个最紧迫公开压力和地图入口；
- 建议按钮只预填输入，不使用“自动执行”视觉；
- 需要判定时在对应玩家消息后显示一张待判定卡，并在结算前禁用新的行动输入；
- 当前目标、附近角色和关键状态先给摘要，详细信息按需展开；
- 调试操作、随机记录和完整 EventLog 默认不与玩家主路径同级；
- 结局后冻结会改变事实的输入，保留回放、总结和返回存档操作。

### 6.4 模态框与 Sheet

- 模态框只用于需要完成或明确取消的任务；浏览型内容优先使用侧栏、全屏页或 Sheet；
- 点击遮罩只能关闭无未保存输入的轻量浮层；
- Compact 使用底部 Sheet 或全屏页，Expanded 使用居中面板或侧栏；
- 打开后焦点进入标题或首个控件，关闭后回到触发控件；
- 模态框内不再创建另一层模态框。

## 7. 核心组件规范

### 7.1 按钮

| 类型 | 样式 | 用途 |
|---|---|---|
| Primary | 金色实心、深色文字 | 当前区域唯一推荐行动 |
| Secondary | 深色表面、金色描边或文字 | 返回、查看、替代行动 |
| Quiet | 透明或弱底色 | 工具栏、筛选、低频操作 |
| Destructive | 错误色弱底、错误色文字 | 删除密钥、丢弃草稿等破坏性操作 |

- 文案使用动词和对象，如“进入梦境”“确认角色”“查看来源”；
- 禁用状态保留标签可读性，并在必要时说明原因；
- 小型 HUD 操作可以视觉紧凑，但命中区域不能缩小；
- 一排按钮过多时按任务分组或转为菜单，不能无限横向滚动。

### 7.2 卡片与面板

Card 只用于表达一个完整对象或信息组，不能成为默认布局容器。

| 组件 | 内容 |
|---|---|
| `NarrativePanel` | PM、NPC、玩家或系统公开消息 |
| `CheckRequestCard` | 行动名、判定名、骰式与单一“掷骰/进行判定”操作 |
| `SituationPanel` | 场景、目标、压力、可见要素和出口摘要 |
| `EntityCard` | 角色、地点、物品等 Definition 驱动对象 |
| `MetricCard` | 标签、当前值、范围/趋势、可选操作 |
| `TaskCard` | 目标、进度钟、状态与下一步 |
| `FormSection` | 一组相关字段、帮助、错误与操作 |
| `StatusBanner` | 成功、警告、错误、离线或保存状态 |

相同对象在 Compact 与 Expanded 中可以改变排列，不能改变标题、状态含义或主操作。

### 7.3 对话

| 说话者 | 强调色 | 对齐与语义 |
|---|---|---|
| PM | `brandPrimary` | 左对齐，承担场景与规则叙述 |
| 玩家 | `narrativePlayer` | 右对齐，宽度不超过主区 76% |
| NPC | `narrativeNpc` | 左对齐，显示公开身份与可见范围 |
| 系统 | 中性灰/语义状态色 | 不伪装成角色发言 |

- 私聊必须显示 `#角色` 或明确“私密”标签，不能只换颜色；
- `@角色` 公开寻址与普通叙事使用不同标签，但保持同一消息结构；
- PM、玩家与 NPC 使用稳定头像；NPC 优先读取世界包头像资产，缺失时回退到姓名首字；
- 头像位于气泡外侧，玩家消息靠右且头像在右，PM 与 NPC 靠左且头像在左；消息气泡使用 12–16 dp 圆角，并保留靠近头像一侧的方向感；
- 正在生成使用同一 PM 容器和轻量状态，不创建跳动的大面积占位动画；
- 待判定卡使用 PM 头像和规则卡片，不伪装成叙事气泡；确认前只显示判定依据，确认后以居中系统消息显示各骰结果、总值和公开档位；
- Provider 原始错误、模型私有正文和内部 ID 不进入对话。

### 7.4 输入与建议

- 输入框最低 48 dp 高，正文使用 `body`，占位文案说明“行动 / @公开 / #私聊”；
- 发送是主操作，但输入为空、仍在运行或会话不可用时必须禁用并解释；
- 建议使用短标签 + 可选理由/取舍，点击后只写入可编辑草稿；
- Compact 最多首屏展示 3 个建议，其余折叠；
- 输入、建议和角色寻址共享焦点与草稿状态，切换地图不清空。

### 7.5 状态与反馈

反馈文案采用“发生了什么 → 影响是什么 → 可以做什么”：

- 成功：简短确认，不抢占叙事；
- 保存中：只在持续超过 300 ms 后显示，避免闪烁；
- 可恢复错误：提供“重试”“补叙述”“修复”之一；
- 不可恢复错误：明确保持了哪些事实，并提供返回或诊断入口；
- 空状态：说明为什么为空，并提供一个合理下一步；
- 加载状态：保留页面骨架，避免在全屏中央只显示转圈。

## 8. 文案风格

界面使用三种明确语域：

| 语域 | 用途 | 示例 |
|---|---|---|
| 叙事语言 | 首页、场景、结局、角色公开介绍 | “穿过茧层，别松开这根丝。” |
| 玩家系统语言 | 建角、存档、网络、错误、设置 | “连接失败，已保存的密钥未改变。请重试。” |
| 创作工具语言 | 识别、验证、来源、安装 | “候选缺少初始场景引用，暂不能试玩。” |

- 同一条反馈不能在诗意表达和技术诊断之间跳变；
- 玩家页面不显示 `war.*`、`station.*`、Schema 名、枚举名和堆栈信息；
- 技术详情放入开发者诊断或创作工具的可展开区域；
- 标题使用名词，操作使用动词，状态使用完整短句；
- 危险与代价只描述玩家已经知道的事实。

## 9. 动效

统一节奏：

| 级别 | 时长 | 用途 |
|---|---:|---|
| Micro | 120 ms | 按压、焦点、选中 |
| Control | 180 ms | Chip、按钮、局部展开 |
| Panel | 240 ms | 侧栏、Sheet、列表插入 |
| Scene | 360 ms | 场景揭示、地图状态更新 |
| Transition | 最长 520 ms | 进入梦境与结局转场 |

- 常驻动效只允许低频呼吸、雾、烛火或少量粒子；
- 不可见页面和组件停止动画；
- 减少动态效果开启时，位移、缩放、视差和粒子关闭，必要反馈改为立即切换或短淡入；
- 同一时刻最多一个叙事焦点动效，不让多个 HUD 数值同时跳动；
- 规则结果必须可以跳过长动画，并先提交事实、后播放表现。

## 10. 可访问性与性能底线

- 普通文字与背景对比度至少 4.5:1，大字与关键图形至少 3:1；
- 键盘焦点使用 `borderFocus` 和形状变化，不能只改变透明度；
- 所有图片提供合适的可访问描述；纯装饰背景不朗读；
- 状态、地图节点、关系和风险同时使用颜色、图标/形状与文字；
- 支持系统字体放大；内容增高时滚动，不能缩字或裁切；
- Desktop 支持完整键盘导航、Enter/Space 激活和 Escape 关闭轻量浮层；
- 三端在最低配置维持 30 FPS；动效、粒子和模糊遵守 `docs/DESIGN.md` 的预算；
- 时间线、EventLog、角色、物品、存档和候选列表不得一次性载入无限内容。

## 11. 验收矩阵

每个新页面或视觉重构至少覆盖：

| 维度 | 最低样本 |
|---|---|
| 世界 | `war-survival`、`station-ai`、未知资产回退 |
| 尺寸 | 360×800、412×915、800×600、1280×720、1440×900 |
| 输入 | 触摸、鼠标、键盘、软键盘打开 |
| 偏好 | 默认、减少动态效果、字体放大 |
| 数据 | 空、加载、正常、长文本、错误、禁用、离线/恢复 |
| 主题边界 | 无题材 ID 分支、语义色不被世界覆盖、隐藏信息不进入 UI |

视觉验收清单：

- 页面属于明确的体验密度；
- 只有一个视觉主行动；
- 标题、正文、说明和元数据能一眼区分；
- 没有新增的硬编码颜色、任意 alpha、间距或圆角；
- 不显示内部 ID、枚举或序列化文本；
- 背景变化后文字仍清楚；
- Compact 没有横向裁切，键盘不遮挡主输入；
- 焦点、错误、禁用和选中不只靠颜色；
- 两个契约世界使用同一组件结构；
- 减少动态效果不会丢失信息或操作。

## 12. 落地计划

### 阶段 0：建立共享基线

1. 固化首页、建角、游戏、存档、设置五个页面的视觉基线截图；
2. 在 `shared:ui-game` 建立唯一的 Theme、Color、Typography、Shape、Spacing、Motion 与 Breakpoint token；
3. 建立共享 Scaffold、Panel、Button、StatusBanner、Field、ChoiceCard 与 EmptyState；
4. 增加禁止页面级十六进制颜色和任意尺寸复制的评审规则。

### 阶段 1：统一聚焦型页面

1. 先重构角色创建，移除内部 ID 和序列化值，补齐步骤、摘要和受控宽度；
2. 让存档、设置与识别工作区使用聚焦型页面骨架；
3. 统一成功、错误、加载、空状态与破坏性操作；
4. 保持 application/use-case、Profile 与世界配置边界不变。

### 阶段 2：收敛主游戏页

1. 将 `GameplayPage` 的局部颜色和尺寸迁移到共享 token；
2. 统一场景条、对话、建议、输入、HUD、角色条和地图面板；
3. 以宽度断点替代各页面不同的 Compact/横竖屏判断；
4. 把调试操作和完整审计从玩家主路径降级到按需入口。

### 阶段 3：跨世界与跨端验收

1. 为两个契约世界生成相同状态集合的视觉回归样本；
2. 完成 Android 窄屏、iOS 编译与 Desktop 1280×720 人工验收；
3. 验证减少动态效果、键盘导航、字体放大与长列表性能；
4. 经试玩确认后再允许新页面引用统一组件，删除旧的一次性样式。

## 13. 完成定义

统一风格完成不以“换完颜色”为标准，而以以下结果为准：

- 首页、角色创建、游戏、存档和设置在遮住标题后仍能被识别为同一产品；
- 不同页面根据任务保持合理密度，而不是复制同一模板；
- 页面只组合语义 token 和共享组件，不重新发明局部设计系统；
- 两个契约世界只更换世界内容和表现资产，不更换交互语义；
- 玩家不会看到内部数据结构，也不会因为背景、尺寸、动效偏好或输入方式而失去信息；
- 规范的验收矩阵进入 UI 变更的日常测试与评审流程。
